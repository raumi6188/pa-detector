# 併用運用のコスト

## 金銭コストは増えません

| 項目 | 課金方式 | 併用による増加 |
|---|---|---|
| J-Quants API | 月額固定のサブスクリプション | **なし** |
| kabuステーション | 口座保有者は無料 | **なし** |
| Gmail SMTP | 無料 | **なし** |
| 電気代 | PCの稼働時間ぶん | 誤差 |

J-Quantsは**リクエスト課金ではなく月額固定**です。回数を増やしても請求は変わりません。
代わりに1分あたりのリクエスト数上限（レートリミット）があるので、
気にすべきはそちらです。

なお、いま最新営業日のデータが取れているので、既に有償プランをご契約のはずです。
無料プランは12週間遅延なので、2026-08-21のデータは取れません。

---

## 実質的なコストはリクエスト数

こちらに無駄がありました。修正しています。

### 修正前（毎日実行した場合）

| 処理 | リクエスト数/日 |
|---|---|
| 株価 `--quotes` | 1〜3 |
| 財務 `--statements` | **285**（400日ぶんを毎日取り直していた） |
| 分割の再同期 | **43**（同じ銘柄を毎日全履歴取得していた） |
| **合計** | **約330** |

### 修正後

| 処理 | リクエスト数/日 |
|---|---|
| 株価 | 1〜3 |
| 財務 `--stmt-days 7` | 5 |
| 分割の再同期 | **0**（新規の分割がある日だけ） |
| **合計** | **約8** |

**約40分の1**になります。

### 何を直したか

**① 財務の遡及日数を引数化** — `days_back` が400日固定で、毎回285営業日ぶんを
取り直していました。既に入っている過去のデータを毎日取り直す意味はありません。
`--stmt-days 7` で直近1週間だけにします。決算は開示日に取れれば十分なので、
7日あれば取りこぼしません。初期構築時だけ `--stmt-days 400` を指定してください。

**② 分割の再同期に台帳を追加** — 直近120日に分割があった銘柄を毎回洗い出し、
その銘柄の**全履歴**（1,223行）を取り直していました。43銘柄あったので、
毎日43回の重い取得が走ることになります。一度再同期すれば同じ分割を
やり直す必要はないので、`resync_log` テーブルで処理済みを記録し、
未処理の分割だけを対象にするよう変更しました。

モックで検証済みです。

```
1回目 : 2銘柄を再同期
2回目 : 0回（重複が排除された）
新規分割が発生 : その1銘柄だけ処理
```

## kabuステーション側

14:00の実行では、板情報を銘柄数ぶん取得します。

| 対象 | リクエスト数 | 所要時間（8req/秒） |
|---|---|---|
| 現在（491銘柄） | 491 | 約1分 |
| プライム全体（1,558銘柄） | 1,558 | **約3分半** |

これはローカル接続なので通信料もかからず、外部APIの制限にも関係しません。
ただし**13:50に起動しないと14:00に間に合いません**。

## 併用で本当に増えるコスト

金銭でも通信でもなく、次の2つです。

**① PCの稼働条件** — 13:50と17:00の両方でPCが起動している必要があります。
14:00のほうはkabuステーションのログインも要ります。
17:00だけなら夕方に起動していればよく、条件はずっと緩くなります。

**② 注意のコスト** — メールが1日2通届きます。
14:00の候補と17:00の確定版で銘柄が重複するので、
「同じものを2回見る」感覚になるかもしれません。

②については、**検証期間を区切るのが現実的**だと思います。
2〜3週間ぶんCSVが溜まれば、確度ランクの閾値が妥当かどうかは判断できます。
そこで14:00を止めるか続けるか決めれば、注意のコストは一時的なもので済みます。

## 日次運用のコマンド

```bat
rem 17:00 の実行（run_pa_eod.bat）
python -m pa_detector.update_db --quotes --statements --stmt-days 7
python -m pa_detector.run_intraday --eod
```

14:00の実行はDBを読むだけなので、J-Quantsへのリクエストは発生しません
（前日夕方の更新で足りています）。

初期構築や、長期間空けた後の復旧では遡及日数を明示してください。

```bat
python -m pa_detector.update_db --quotes --from 2024-08-01
python -m pa_detector.update_db --statements --stmt-days 400
```
