`stock_data.db` の実際のスキーマに合わせて `store.py` を書き換え、
DB更新スクリプト `update_db.py` を追加した。

## 実データで確認できたこと

`stock_data.db` をそのまま読ませて、491銘柄で143件のヒットを確認済み。
PER 137/143、PBR 143/143 が算出できている。

同時に、**放置すると誤った結果を出す問題が2つ見つかったので修正した。**

### 修正1　分割調整（これは深刻だった）

`quotes` の `open_p` / `high_p` / `low_p` / `close_p` は**未調整**で、
調整済みなのは `adj_close` だけだった。

9533（2026-03-30に1:4分割）で見ると：

| 日付 | close_p | adj_close |
|---|---|---|
| 03-27 | 4,862 | 1,215.5 |
| 03-30 | 1,243.5 | 1,243.5 |

`close_p` をそのまま使うと**分割日に −75% の暴落と誤認**し、
該当銘柄が一斉に「安値を割った」と検知される。

比率 `r = adj_close ÷ close_p` を日ごとに求め、O/H/L に掛けて復元した。
出来高は逆に `r` で割る（分割で株数が増えるため）。
修正後、9533の分割日前後の変化率は 0.86% に収まることを確認した。

### 修正2　PERが4倍に出ていた

`statements` の `eps` は「期首からの累計」であって通期の値ではない。
中外製薬の直近は1Q時点の 70.13 で、これをそのまま使うと **PER 112.5倍**と表示された。

TTM（直近12か月）に改めた：

```
TTM EPS = 当期累計 ＋ 前期通期 − 前年同期累計
中外製薬 = 70.13 + 263.73 − 59.09 = 274.77 → PER 28.7倍
```

なお、伊藤園（147.7倍）や小林製薬（141.8倍）が高く出るのは**正しい**。
前者は3Qに大きな損失、後者は通期利益が135円→49円へ落ちており、
TTMがそれを正しく反映している。数値が跳ねている銘柄は決算内容を見てほしい。

### そのほかの対応

- **コードが5桁**（`13320` = 1332 + 末尾0）。kabuステーションAPIは4桁なので相互変換を追加。メール表示も4桁にした
- **BPSが四半期開示に入っていない**（36%）。本決算(FY)の最新から取るようにした
- **配当データがない**。`update_db.py --dividends` で `dividends` テーブルを作れば利回りも出る

## いま必要な作業

### ステップ1　ファイルを差し替える

`store.py` `kabus.py` `mailer.py` を新しいものに置き換え、`update_db.py` を追加する。

### ステップ2　DBを更新する（必須）

**最終営業日が 2026-05-29 で、約3か月古い。** このままでは5月末の足を
「前日」として判定してしまう。

```bat
set JQUANTS_API_KEY=（APIキー）
set PA_DB_PATH=C:\quant\stock_data.db

rem 銘柄一覧を最新化（491銘柄 → プライム全銘柄に増える）
python -m pa_detector.update_db --refresh-listed

rem 株価の差分更新（5月末〜今日。数分かかる）
python -m pa_detector.update_db --quotes

rem 財務と配当
python -m pa_detector.update_db --statements --dividends
```

以降の運用では、毎朝これ一発で済む：

```
python -m pa_detector.update_db --all
```

**銘柄数について。** いまの `stocks` は491銘柄だが、東証プライムは約1,600ある。
`--refresh-listed` を打つと全プライムが入る。**ただしユニバースが3倍になるので、
株価の初期取得に時間がかかり、ヒット数も増える。** 現状の491銘柄で
まず動かしてみて、慣れてから広げるという順序でもいい。

## update_db.py について

| オプション | 内容 |
|---|---|
| `--refresh-listed` | 銘柄一覧を更新。`--prime-only` でプライムだけに絞れる |
| `--quotes` | 株価。DBの最終日から今日まで差分取得。`--from 2024-08-01` で期間指定 |
| `--statements` | 財務。直近120日ぶんの開示 |
| `--dividends` | 配当。`dividends` テーブルを作る（利回り表示に必要） |
| `--all` | 全部。毎日の運用はこれ |

日付単位で取得しているので、銘柄単位より大幅に速い。

**分割の再同期を自動で行う。** 分割が起きると過去すべての `adj_close` が
変わるため、差分更新だけでは古い行が古いままになる。
`--quotes` は直近90日に分割があった銘柄を検出し、その銘柄の全履歴を
取り直すようにしてある。
