# GitHub Actions で自動配信する

ノートPCの電源が切れていても、毎営業日17時過ぎにメールが届くようにします。

EOD運用（確定足）に切り替えたことで kabuステーションが不要になったため、
クラウドで完結できるようになりました。場中モードはクラウドでは動きません。

---

## 設計上の判断

### DBはリポジトリに置けません

GitHubは**1ファイル100MB**が上限です。いまのDBは835,123行で約97MB、
今後さらに増えるので git 管理は不可能です。

そこで **Actionsのキャッシュ** に載せて持ち回ります。

```
キャッシュから復元 → 差分更新（数秒） → 検知 → メール → キャッシュ保存
```

キャッシュが無い初回だけ、400日ぶんを取得してフルビルドします（10分程度）。
**キャッシュのoutputに依存せず、DBファイルが実在するかで分岐**させているので、
初回・キャッシュ失効・破損のいずれでも正しくフルビルドに落ちます。

キャッシュは7日間アクセスが無いと消えますが、平日毎日動くので維持されます。
連休で消えても、次の実行で自動的に再構築されます。

### 結果CSVはリポジトリにコミットします

1日あたり数十KBなので git 管理して問題ありません。
`results/` に積み上がるので、これがそのまま第9章の検証データになります。
HTMLは成果物（artifact）として30日間保存されます。

---

## セットアップ

### ① リポジトリを作る

GitHubで新規リポジトリを作成します。**Private を推奨**します。
Secretsは公開リポジトリでも安全ですが、投資判断のロジックを
公開する必要はないので。

Free プランの Private リポジトリは **月2,000分** まで無料です。
1回あたり2〜3分なので、月20営業日で60分程度。十分収まります。

### ② ファイルを置く

```
リポジトリ/
├─ .github/
│   └─ workflows/
│       └─ pa_detector.yml
├─ pa_detector/
│   ├─ __init__.py
│   ├─ config.py
│   └─ …（11ファイル）
├─ results/
│   └─ .gitkeep
├─ requirements.txt
└─ .gitignore
```

`.gitignore` で `*.db` と `run_pa_eod.bat` を除外しています。
**認証情報の入ったbatファイルを誤ってコミットしないため**です。

### ③ Secrets を登録

リポジトリの **Settings → Secrets and variables → Actions → New repository secret**

| 名前 | 値 |
|---|---|
| `JQUANTS_API_KEY` | J-QuantsのAPIキー |
| `PA_SMTP_USER` | Gmailアドレス |
| `PA_SMTP_PASSWORD` | アプリパスワード16桁 |
| `PA_MAIL_TO` | 送信先アドレス |

ローカルで使っているものと同じ値です。

### ④ 手動で試す

**Actions** タブ → 左の「プライスアクション検知（日次）」→
右上の **Run workflow**。

初回はキャッシュが無いのでフルビルドが走り、10分程度かかります。
`dry_run` にチェックを入れればメールを送らずHTMLだけ生成できます。
まずはこれで試すことを勧めます。

ログで各ステップの出力が見られます。`DBの状態` のところで

```
最終営業日 : 2026-08-24（0日前）
収録銘柄数 : 4444（stocks のプライム 1558）
配当テーブル: あり 18,861行
✓ 問題なし
```

と出れば正常です。

### ⑤ 自動実行を確認

以降は平日17:15（JST）に自動実行されます。

## 実行時刻について

cron は `15 8 * * 1-5`（08:15 UTC = 17:15 JST）に設定しました。

**GitHubのスケジュール実行は混雑時に数十分遅れることがあります。**
これは仕様で、避けられません。17:15設定なら17:15〜18:00の間に届く、
と考えてください。

早めたい場合、J-Quantsの株価更新が16:30頃なので、
16:45（`45 7 * * 1-5`）より前にはできません。
遅延を見込むと17:15は妥当な設定だと思います。

厳密な時刻が必要なら、遅延しないスケジューラ（クラウドのcronサービス等）から
`workflow_dispatch` を叩く方法もありますが、そこまでする必要は無いでしょう。

---

## 休場日の扱い

祝日・年末年始は市場が閉まっているため、DBの最終営業日が当日になりません。
`--skip-if-not-today` を付けてあるので、その場合は**何もせず終了**します。
空メールは届きません。

```
DB最終営業日 2026-08-21 ≠ 本日 2026-08-24 → 休場日と判断して終了
```

---

## ローカル運用との併用

両方動かすと**メールが2通届きます**。どちらかに寄せてください。

ローカルを止める場合：

```
schtasks /Delete /TN "PA検知EOD" /F
```

ローカルを残す意味があるとすれば、場中（14:00）の候補メールです。
これはkabuステーションが要るのでクラウドでは動きません。
14:00の候補と17:15の確定版を比べたい場合は、
**14:00だけローカル、17:15はクラウド**という分担が合理的です。

---

## 設定を変えるとき

`.github/workflows/pa_detector.yml` の `env` を編集してコミットします。

```yaml
      PA_MIN_TURNOVER: "50000000"
      PA_CONF_B: "0.5"
      PA_EXCLUDE: "14"
```

ローカルの `run_pa_eod.bat` と値を揃えておかないと、
同じ日に違う結果が出て混乱します。

## うまくいかないとき

| 症状 | 原因 |
|---|---|
| `JQUANTS_API_KEY が未設定です` | Secretの名前が違う。大文字小文字を確認 |
| SMTPエラー | アプリパスワードが正しくない。通常のパスワードでは弾かれる |
| `git push` が失敗 | `permissions: contents: write` が効いていない。ymlを確認 |
| 毎回10分かかる | キャッシュが効いていない。ログの「DBキャッシュを復元」を確認 |
| メールが届かない日がある | 休場日か、cronの遅延。Actionsタブで実行履歴を確認 |

ログは Actions タブの各実行から見られます。
エラーが出たらそのログを貼ってください。
