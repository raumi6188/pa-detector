# 確定足モード（17:00運用）への切り替え

kabuステーションを使わず、J-Quantsだけで完結させる運用です。

---

## なぜ15:35ではなく17:00か

**J-Quantsの株価データは大引け後、16:30頃の更新**です。15:35の時点ではまだ
当日分が存在しないため、15:35に送ろうとすると結局kabuステーションが必要になります。

15:30の大引けは既に過ぎているので**その日の引けでは入れない**。
依存だけ残って目的は果たせない、という中途半端な形になります。

同じ「その日は入れない」なら、17:00まで待ってJ-Quantsだけで完結させたほうが得です。

---

## 消えるもの

| | 14:00（場中） | 17:00（確定足） |
|---|---|---|
| データ源 | kabuステーション | **J-Quantsのみ** |
| kabu起動・ログイン | 毎朝必要 | **不要** |
| PC稼働 | 場中に必須 | **夕方だけ** |
| 実行時間 | 約3分半 | **数秒** |
| 出来高の日中補正 | 較正が必要 | **不要** |
| 使える型 | 17型 | **18型すべて** |
| 判定の性質 | 後場で剥落しうる | **確定。覆らない** |

`calibrate_volume.py` も出番がなくなります。

## 失うもの

**当日の引けで入れません。** 翌営業日の寄り以降になるため、
一晩ぶんのギャップリスクを引き受けることになります。

## 設定手順

### ① `run_pa_eod.bat` を `C:\quant\` に置く

中の環境変数（APIキー、Gmail）を埋めてください。

### ② 試運転

```
cd /d C:\quant
set PA_DB_PATH=C:\quant\stock_data.db
set PA_OUT_DIR=C:\quant\pa_out
python -m pa_detector.run_intraday --eod --dry-run
```

`PA_OUT_DIR` にHTMLが出ます。

### ③ スケジュール登録（管理者権限のコマンドプロンプトで）

```
schtasks /Create /TN "PA検知EOD" /TR "C:\quant\run_pa_eod.bat" ^
  /SC WEEKLY /D MON,TUE,WED,THU,FRI /ST 17:00 /F
```

既に14:00のタスクを登録済みなら、不要なら削除してください。

```
schtasks /Delete /TN "PA検知" /F
```

### ④ 両方を併用する場合

14:00の場中候補と17:00の確定版を両方受け取ることもできます。
その場合は両方のタスクを登録してください。件名で区別できます。

- 場中: `[PA検知/場中候補] 2026-08-24 — 45件`
- 確定: `[PA検知/確定] 2026-08-24 — 52件`

**14:00で出た候補のうち、何件が引けまで残ったか**を比べられるので、
確度ランクの閾値（1.5と0.5）が妥当かどうかの検証材料になります。
しばらく併用して確かめる、という使い方は合理的だと思います。

## 今回あわせて直した点

### 型4が使えるようになりました

「引け際の売り叩きの否定」は、CLVが引け際の値動きそのものなので
場中では原理的に判定できず、既定で除外していました。
確定足では判定できるので、`--eod` のとき自動的に対象に含めます。

ただし実装に2つ問題があったので修正しました。

**問題1** 確度判定が `monotone_ok`（当日の高値・安値に非単調に依存するか）で
無条件にCランクを付けていました。これは「引けまでに剥落しうるか」の話であって、
確定足では問う意味がありません。場中限定の条件に変更しました。

**問題2** 型4の基準線を「当日レンジの75%地点」に置いていたため、
条件が成立した時点で余裕が必ず微小になり、確度ランクが機能しませんでした。
基準線を「弱かった2日間の終値」に変更し、そこからの奪回幅で強さを測るようにしました。

修正後、実データで正しく検出されることを確認しています。

```
[B] 4578 大塚ホールディングス 余裕1.31
    弱い引け2日（CLV 0.20, 0.20）→ CLV 1.00 で11310を奪回
```

### メールの文面をモードで切り替え

確定足のときに「未確定足」と書かれる矛盾を解消し、
価格列のラベルも「現在値」→「終値」に切り替わるようにしました。

「余裕」の説明も変えています。場中は「引けまで剥落しにくさ」ですが、
確定足では「基準線をどれだけ明確に奪回したかの強さ」になります。
値が大きいほど明確な奪回ですが、その分エントリー価格は基準線から離れる、
というトレードオフは残ります。
